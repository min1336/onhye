# 온혜 AI 호출 방어 — 2026-10-28

## 적용 범위

AI는 관심 분야를 분류하는 제한된 JSON만 반환한다. 검색·페이지 이동·조건 수정·혜택 저장에는 AI를 쓰지 않는다. 도구 실행, 임의 URL 조회, SQL 실행, 자동 신청 권한은 없다. 기존 입력 검증·금액 마스킹·출력 스키마·원문 근거 검증·12초 제공업체 요청 제한·자동 재시도 금지를 유지했다.

명확한 인사·사용법·일부 범위 밖 질문은 서버 고정 안내로 처리한다. 이는 전체 공격 탐지기가 아니다. 우회 문구가 분류기에 도달할 수 있으므로 구조화 출력과 권한 제한, 호출 예산으로 피해를 제한한다. '해킹 피해 지원', '성폭력 피해 지원' 같은 정상 질문은 키워드만으로 차단하지 않는다.

## 유료 요청에 강제하는 통제

- 익명 서명 쿠키(HttpOnly, SameSite=Strict, 공개 HTTPS에서는 Secure), 세션별 CSRF 토큰, 설정된 Origin 확인.
- 쿠키는 계정 인증이 아니다. 삭제하면 새 세션이 생긴다. IP 및 전역 한도와 공개 환경의 Turnstile 검증을 함께 적용한다.
- 요청 ID 재사용은 409로 거부한다. 자동 재시도와 결과 원문 캐시는 없다.
- SQLite 즉시 트랜잭션에서 원자적으로 예약: 세션 3회/분·10회/UTC일, IP 20회/분, 전역 100회/UTC일, 세션 동시 1개·전역 동시 3개.
- 예약은 제공업체 실패에도 유지한다. 처리 중 표시의 유효기간은 60초이며 실제 제공업체 요청 제한은 12초다. 취소 전달 지연 등 제공업체 내부 실행까지 정확히 보장하지 않는다.
- 서버 재시작과 같은 SQLite 파일을 쓰는 프로세스 사이에 한도가 유지된다. 데이터베이스 장애 시 AI를 호출하지 않는다. 일반 API는 유효한 경로·메서드를 먼저 확인한 뒤 소켓 IP 전체 180회/분과 경로별 GET 120회·POST 60회/분 제한을 적용한다. 제한 저장소는 IP별로 최대5,000개를 보관하며 포화 시 오래된 항목을 교체한다. 임의 경로를 버킷으로 저장하지 않는다.
- 공개 환경에서는 Turnstile을 서버에서 검증하고 성공·hostname·action을 모두 대조한다. 실패·장애는 차단한다. localhost 개발 외에는 PUBLIC_ORIGIN(HTTPS)과 두 키가 모두 필요하다. NODE_ENV=production도 이 규칙을 적용한다.
- 한도·장애·봇 검증 실패와 관계없이 'AI 없이 직접 분야 선택'과 전체 목록은 이용할 수 있다.

## 저장 정보와 운영

`.private/ai-guard.sqlite`에는 서명용 비밀, 중단 상태, HMAC 처리한 익명 세션·IP·요청 ID·입력 해시와 시각·처리 상태만 기록한다. 상담 원문·프로필·AI 답변은 기록하지 않는다. 파일 권한은 0600, 신규 디렉터리는 0700이다. 요청 기록은 새 유료 호출 예약 시 당일과 이전 2 UTC일만 남긴다. SQLite 삭제 영역의 즉각적인 물리 삭제를 보장하지는 않는다. DB는 공개 폴더와 버전 관리에 넣지 않는다.

즉시 중단/해제(같은 AI_GUARD_FILE을 사용해야 함):

```sh
node --env-file-if-exists=.env.local scripts/ai-control.mjs pause
node --env-file-if-exists=.env.local scripts/ai-control.mjs resume
```

중단은 새 유료 호출에 적용되며 이미 진행 중인 호출을 취소하지 않는다. `AI_ENABLED=false`도 새 서버 시작 시 유료 호출을 비활성화한다. 직접 검색은 유지된다.

## 공개 배포 전 필요한 외부 설정

1. HTTPS 주소를 `PUBLIC_ORIGIN`에 정확한 Origin 형식으로 설정한다(끝 슬래시 없음).
2. 해당 호스트에 등록한 Turnstile의 사이트 키·서버 비밀 키를 설정한다. 브라우저에는 사이트 키만 전달한다.
3. `AI_GUARD_FILE`을 영속 로컬 디스크에 지정하고 단일 인스턴스로 운영한다. 임시 파일 시스템·각기 다른 DB의 다중 인스턴스에는 전역 한도를 보장하지 않는다. 이런 배포에는 공유 원자적 저장소로 교체해야 한다.
4. Google Cloud에서 최소 권한 서비스 계정과 Vertex AI 권한을 확인한다. 결제 알림과 별개로 지원되는 Cloud Spendcap을 실제 프로젝트·서비스에 설정하고 확인한다. 현재 계정의 Spendcap·IAM 설정은 이번 작업에서 변경하거나 확인하지 않았다.
5. 프록시 뒤에서는 임의 X-Forwarded-For를 신뢰하지 않는다. 현재는 소켓 IP만 사용하므로 프록시 이용자가 IP 한도를 공유한다. 실제 배포 플랫폼을 정한 뒤 신뢰 프록시 설정을 추가해야 한다.

100회는 요청 수 상한이며 원화 청구 한도가 아니다. 제공업체 토큰 가격·진행 중 요청·청구 집계 지연에 따른 비용 위험은 별도다. Turnstile 키와 공개 도메인이 없는 현재 환경에서는 공개 봇 검증을 실서비스로 확인하지 않았다. 로컬 개발에서는 봇 검증을 요구하지 않는다.

## 개발 파일 제공 차단

Vite 미들웨어로 넘기기 전 .private·.git·환경파일·SQLite 및 보조파일을 차단한다. 실제 파일 경로를 확인해 심볼릭 링크도 검사하며 Vite fs.deny에도 비공개 경로를 등록한다. 기존 영속 DB는 옮기거나 삭제하지 않아 호출 예산과 세션 서명 상태를 보존한다. 공개 배포는 여전히 production 모드와 영속 저장소가 필요하다.
